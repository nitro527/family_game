# 맵 입체화 계획 (2026-10-11, 장기 프로젝트)

사용자: "크로노 트리거처럼 입체감 있게 — 언덕이나 지하실처럼 계단식 지형, 약간 쿼터뷰로 바꿔서 거리감이 느껴지게. 에셋을 다 업데이트해야 하니 장기 프로젝트."

## 지금 상태
- 맵 = 36×24 글자 칸 (`Sim/WorldMap.cs`), 높이 없음. 걸을 수 있는지는 글자로만 정한다.
- 그림 = `View/MapPainter.cs`가 맵 한 장을 **텍스처 하나로 통째로** 그린다(48px 칸, 노이즈 땅, 부드러운 길·물 경계, 동굴만 3/4 절벽면).
- 나무·집·바위 같은 소품도 그 텍스처에 같이 구워진다. 그래서 캐릭터는 늘 소품 **앞**에만 서고, 나무 뒤로 지나갈 수 없다.
- 카메라는 정면 위에서 내려다보는 직교 카메라(orthographic)예요.

## 크로노 트리거 느낌을 만드는 것 (목표)
1. **높이 층**: 언덕·절벽·지하실·2층처럼 칸마다 높이(0~3)가 있다. 높은 땅의 남쪽 가장자리에 절벽면이 보이고, 그림자가 진다.
2. **계단·비탈**: 높이가 다른 곳은 계단·비탈·사다리 칸으로만 오르내린다.
3. **앞뒤 가리기**: 큰 나무 줄기 뒤, 집 지붕 아래, 다리 밑으로 캐릭터가 지나가면 가려진다(y 정렬 스프라이트).
4. **거리감**: 정면 직교 대신 살짝 기울인 시점(약 20~30°). 먼 쪽이 조금 작고 위로 올라가 보인다.

## 단계 (한 단계씩 끝내고 프로브·빌드)
| 단계 | 할 일 | 확인 |
|---|---|---|
| **0. 시점 실험** | 같은 초원 맵을 ① 지금 그림 + 원근 카메라 기울이기(바닥은 눕히고 캐릭터는 세운 스프라이트) ② 직교 3/4(크로노 트리거 방식, 그림으로만 깊이)로 찍어 비교 | 🙋 사용자가 고른다 |
| **1. 높이 데이터** | WorldMap에 높이 층(글자 맵 옆 숫자 맵), 계단 칸, 이동 규칙(같은 높이 또는 계단으로만). 맵 데이터를 JSON(`maps/*.json`)으로 옮기는 것도 이때 | 스모크: 출발점에서 보스·마을·보물상자·이벤트 칸까지 길이 모두 이어지는지(BFS) |
| **2. 높이 그림** | MapPainter가 높이별로 그림: 절벽면(남쪽), 위 가장자리 테두리, 높은 땅 그림자, 계단·비탈 그림. 동굴 3/4 절벽 코드를 일반화 | 맵 그림 비교 |
| **3. 소품 세우기** | 큰 소품(나무·집·바위·책장)을 텍스처에서 떼어 y 정렬 스프라이트로. 밑동은 막히고 윗부분은 캐릭터를 가린다 | 프로브: 나무 뒤를 지나가면 가려지는지 |
| **4. 맵마다 적용** | 초원 언덕·연못 둑 → 동굴 층·지하 계단 → 사막 모래 언덕 → 용암 단층 → 눈 언덕·얼음 → 도서관 2층·사다리 → 숲 큰 나무 뿌리 언덕. 마을: 집 안 지하실 | 맵마다 프로브 통과 |
| **5. 에셋 다시 그리기** | 3/4 각도 소품·절벽·계단 그림(로컬 Qwen), 타일 질감. 낮은 품질부터 하나씩 | 그림 확인 |
| **6. 연출** | 높은 곳에서 떨어지는 점프, 계단 발소리, 언덕 위에서 보는 경치(가족 앨범 자리와 연결) | 프로브 |

## 주의
- 이동 규칙이 바뀌면 지금의 길·이벤트·찾기 부탁 반짝이 자리가 막힐 수 있다 → 1단계의 "길 이어짐" 스모크 테스트를 먼저 만든다.
- 세이브 위치(X, Y)는 그대로 쓴다. 높이는 칸에서 바로 알 수 있으니 세이브에 넣지 않는다.
- 맵 크기(36×24)와 칸 크기(48px)는 유지한다. 바꾸면 모든 좌표 데이터가 흔들린다.
- 🙋 시점(원근 기울이기 vs 직교 3/4)은 0단계 그림을 보고 사용자가 정한다.
